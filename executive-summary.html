Why the portal error “Predicted values must be in range [0, 1]” can happen

The public GEMS format requires finite [0,1] values inside the data footprint and null/NaN outside it. If a submission writes zeros (or any finite value) outside the footprint instead of NaN, a strict whole-array range check can reject the file even though every in-footprint pixel is valid. This TIF uses NaN outside the footprint and passes the published-format check. Portal behavior is unverified — local format validation is not organizer acceptance.

How to make a submission into the contest

  1. Get the competition template. Download sample_submission.tif from the DrivenData data tab (requires login). This is the exact grid (CRS, shape, transform) your TIF must match.
  2. Generate or obtain a prediction TIF. The file must be a single-band float32 GeoTIFF on the template grid: finite values in [0,1] inside the footprint, null/NaN outside. The unique TIF linked above meets this contract against the pinned grid reference, but the organizer template itself requires DrivenData access.
  3. Validate locally. Run python scripts/validate_submission.py your-file.tif --template data/raw/sample_submission.tif. All checks must pass — especially finite_and_in_range_inside_footprint and null_outside_template_footprint. A whole-array finite diagnostic is advisory only; the public spec permits NaN outside.
  4. Choose a unique name and note. Filename must be unique within your submission history. Note is a short comment (≤140 chars) to tell submissions apart, e.g. “clustering with k=25” or the run name above.
  5. Upload on DrivenData. Go to the submission page, choose your .tif (or .zip containing one .tif), paste the note, and submit. Up to three feedback submissions per week are allowed; one final selection is scored on both label sets.
  6. Do not submit a duplicate. If your dots overlap an existing registry raster by >70% within 3 px, or your surface rank-correlation exceeds 0.90, stop — that lane is duplicate-stopped.

Protocol before any future slot

What must happen before a submission is approved

  1. Obtain a single assigned scientific lane and explicit resolution of the literal registry constraint; do not reduce dot budget merely to evade the stop.
  2. Pre-register whole-segment, spatially buffered hide-and-recover folds; derive catalogue features only from visible faults; audit every feature for leakage (AUC > 0.90 blocks interpretation).
  3. Beat the current same-protocol control with a paired 95% CI lower bound > 0; check surface and final dots against the complete registry; validate exact saved bytes.
  4. Require separate slot-selector approval. A local format pass is not an upload authorization.
