File contract

Before you upload

  • One GeoTIFF band; data type float32.
  • Projected CRS matches the provided grid: UTM zone 11N, EPSG:32611.
  • 100 m pixels and the exact template shape, bounds, and geotransform.
  • Every cell of the file — inside and outside the footprint — is finite and in the closed interval [0, 1] when you upload the portal-safe -zeros.tif variant (0.0 outside).
  • The official sample template itself encodes the outside area as NaN. That template-conformant copy is kept for research (-nan.tif), but a NaN cell anywhere can trip the form's range check, so upload the -zeros.tif file.
  • Use the organizer-provided sample template; never invent the footprint or infer the grid from a screenshot.

Grid requirements come from the official competition problem description and submission form text. The local validator checks them against the downloaded template but cannot guarantee portal acceptance.

Range-error fix

“Predicted values must be in range [0, 1]”

Root cause (measured + independently corroborated): an elementwise range test treats every NaN as out of range — including the NaN cells outside the scoring footprint, which the official sample template itself contains (measured on the pinned template: 7,111,787 NaN cells outside, 5,167,373 finite inside). The GEMSDOE25 site reached the same conclusion independently for an earlier failure and publishes zeros-outside fallback files for exactly this reason.

  1. Download the -zeros.tif (portal-safe) variant from this page and upload that file. It is finite everywhere: 0.0 outside the footprint, predictions unchanged inside.
  2. If you build your own file, run python scripts/make_portal_safe.py YOURFILE.tif — it rewrites NaN cells outside the footprint to 0.0 and proves the in-footprint values are unchanged.
  3. Check before uploading: python scripts/validate_submission.py FILE-zeros.tif --template data/raw/sample_submission.tif --portal-safe must pass all checks, including portal_range_all_pixels.
  4. Do not silently clip or rescale bad model values; fix the upstream model/output and rebuild.
python scripts/validate_submission.py outputs/<candidate>-zeros.tif --template data/raw/sample_submission.tif --portal-safe
Manual upload in DrivenData

Five steps, after the candidate clears holdout

The site does not submit files for you. An authorized competition account is required for the upload.

Download a .tif

Download the portal-safe file — the name ends in -zeros.tif. That variant has finite values everywhere (0.0 outside the footprint) and will not trigger the form's range error; its predictions inside the footprint are byte-identical to the -nan.tif research copies. Two files are available: the project's own GEMSDOE30 candidate (portal-safe, SHA-256 recorded in its manifest) — 4-fold OOF surface, adaptive dots, not holdout-promoted — and the external D2.8 research TIFF (portal-safe). Submitting either is the owner's decision; use the note below verbatim so the record is honest.

Open the official competition

Sign in through your authorized account, open the DOE GEMS competition, choose Submit in the sidebar, then Make new submission. The form describes a single-band GeoTIFF (.tif) or a .zip containing one GeoTIFF.

Open the competition homepage ↗

Choose the exact TIFF

Under File to submit, select the checked .tif file (or a ZIP containing only that one TIFF). Verify the filename matches the manifest and that the hash/size is the intended run.

Enter a unique name and short note

The generated filename is unique, for example GEMSDOE30_boundary300m_20261003T120000123456Z_ab12cd34.tif. Paste a short method comment in Note (optional) so future comparisons are identifiable.

GEMSDOE30 4-fold OOF GBM surface; adaptive Poisson-disk dots (500 m min spacing); portal-safe zeros-outside; proxy gate failed vs uniform - not holdout-promoted

This note matches the built file's manifest and the download label. Never claim a score that has not been verified; the form's note is for distinguishing submissions, not for asserting an unverified result.

Submit and record the outcome

Submit once, wait for the platform's response, and save the submission ID, note, file SHA-256, public score, date/time, and whether the score is public or private. Do not infer a result from a local holdout or another project's page.

A single fold is only a screen: use all frozen folds and a fresh-seed confirmation. The seed-30 loss screen passed the first test and failed the second. The initial geometry weight is a test setting, not a selected optimum.

Competition limits worth remembering

  • The public leaderboard is not the private test set; a public increase can be overfit.
  • The official rules allow up to three weekly platform submissions and require one selected final submission for both prize rounds. Confirm current rules and deadline before any upload.
  • The public leaderboard changes over time. DrivenData Terms of Use prohibit automated monitoring/copying, so this page uses dated snapshots rather than a scraper.
  • The 2026 homepage and rules PDF show different deadline times (11:59 p.m. UTC versus 5:00 p.m. ET); confirm the controlling cutoff with the organizer.
  • Rules require a narrative disclosure of generative-AI use if applicable. Maintain a truthful method and tool-use record for the eventual submission package; the current-session disclosure draft must be updated and entrant-approved before use.
