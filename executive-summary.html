How to read the decision

Green means go. Anything else means stop.

  1. Look at the banner on the home page.

    Only a green OK TO SUBMIT pill, rendered from the machine-verified readiness receipt, permits submission. This session shows DO NOT SUBMIT.

  2. Optional: re-run the decision yourself.

    python scripts/verify_current_run.py --require-promote exits 0 only when every gate passes for the exact bytes (exit 2 = do not submit; exit 1 = evidence broken). There is no human-inspector override.

  3. When a file is approved:

    download the primary .tif (finite 0/1 everywhere, zeros outside the footprint), sign in at the official GEMS competition → Submissions, upload the single file (no ZIP), and paste the 140-character note shown with it.

  4. Mind the slot rules.

    Weekly limits and the one final-submission choice are set by the official rules; this repository never uploads or spends slots.

  5. Record the organizer result.

    Add the returned score, submission ID and file SHA-256 to docs/score-ledger.csv as ORGANIZER-CONFIRMED.

About “Predicted values must be in range [0, 1]”

Finite everywhere.
Zero outside.

NaN is not inside [0, 1], so a whole-array range check can reject NaN-outside files. Approved files from this pipeline ship a primary version with no NaN anywhere (exactly 0 or 1 in every cell, 0 outside the footprint — the owner-reported accepted encoding of H33 and GEMSDOE36) and an alternate with NaN outside, matching the problem page's “null or nan” wording.
