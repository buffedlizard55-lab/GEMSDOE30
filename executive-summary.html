Official DrivenData submission procedure (verified 2026-10-25)

Exact steps when a future run turns every gate green.

  1. Verify automated promotion exit code 0.

    Run python scripts/verify_tad_run.py --require-promote (or python scripts/verify_current_run.py --require-promote). Only proceed when exit code is 0 (ok_to_submit = true, meaning format [0, 1], 144+ feature canaries, 190+ registry surface & dot novelty, and paired spatial-block holdout 95% CI lower bound > 0 have all passed).

  2. Confirm weekly 3-slot allowance & deadline window.

    Per official DOE/NLR Prize Rules PDF (96647.pdf), automated feedback is capped at 3 submissions per rolling 7-day week, and entrants select one single final submission before the deadline for both Phase 1 ($50k: 5 × $10k) and Phase 2 ($250k: $100k/$70k/$40k/$25k/$15k). Deadline discrepancy alert (IR-TAD-02): DrivenData lists Dec. 3, 2026, 11:59 p.m. UTC, whereas NLR Rules PDF Appendix A.1 specifies 5:00 p.m. ET (22:00 UTC) on Dec. 3, 2026—always submit well before 5:00 p.m. ET (22:00 UTC)!

  3. Download the primary -zeros.tif GeoTIFF (never HTML/JSON).

    Download the hash-verified single-band float32 GeoTIFF (EPSG:32611, 3,730 × 3,292, 100 m grid). The primary -zeros.tif encodes 0.0 outside the valid footprint with nodata=None so every one of the 12,279,160 cells lies strictly inside [0.0, 1.0] (preventing whole-array "Predicted values must be in range [0, 1]" rejections), while companion -nan.tif provides the documented NaN-outside encoding.

  4. Upload on DrivenData & paste the ≤140-character note.

    Sign into an eligible account on DrivenData GEMS (Competition 306) → open Submissions → Make a submission → select the verified .tif under File to submit → paste the run card's ≤140-character note (generative AI usage is permitted and must be disclosed in winning documentation, excluded from word count per 96647.pdf).

  5. Log the organizer receipt before claiming ORGANIZER-CONFIRMED.

    Record the returned DrivenData timestamp, file SHA-256, and 4-decimal DTI score in docs/score-ledger.csv. Never label a HOLDOUT-DTI or analytical projection as ORGANIZER-CONFIRMED.

Preventing "Predicted values must be in range [0, 1]"

Automated whole-array & in-footprint gates.

The documented GEMS problem specification requires a single-band float32 GeoTIFF in [0, 1] inside the valid footprint and null/NaN outside, whereas the official reference notebook writes predictions without an explicit nodata tag (all cells finite in [0, 1]). If a portal validator evaluates arr.min() >= 0 and arr.max() <= 1 prior to masking NaN or encounters unmasked -9999/-3.4e38 feature sentinels, it raises "Predicted values must be in range [0, 1]".

Our automated release pipeline eliminates human inspection by verifying both contracts on disk: -zeros.tif guarantees all 12,279,160 pixels are finite {0.0, 1.0} in [0, 1], and -nan.tif passes all 12 checks of gemsdoe30.submission.validate_submission_file.
