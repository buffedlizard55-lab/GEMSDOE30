Executive summary · manual competition submission

How to submit—when a candidate is approved

This page is the exact submission checklist. It intentionally does not offer a TIFF while none has passed the scientific holdout, uniqueness, provenance, and local format gates. A format-valid raster is not automatically a good prediction or organizer-accepted submission.

Competition file contract

Validate the exact GeoTIFF

  • One-band GeoTIFF (`.tif`), 32-bit floating-point predictions.
  • Match the organizer sample template's CRS, shape, bounds, and geotransform.
  • Every prediction inside the valid footprint must be finite and in [0, 1]. This check addresses the reported portal error “Predicted values must be in range [0, 1]”.
  • Outside-footprint encoding must follow the current official problem specification; do not assume a local whole-array range diagnostic is the portal validator.
  • Use the organizer sample template, never infer the footprint from a screenshot or feature-band mask.

Review the official problem description ↗ and official rules PDF ↗. Local validation is not organizer acceptance.

Local format validator

Run this only on the final candidate

After a candidate passes the preregistered holdout and registry-similarity tests, compare its output to the pinned submission template:

python scripts/validate_submission.py outputs/CANDIDATE.tif \ --template data/raw/sample_submission.tif \ --json docs/research/format-checks/CANDIDATE.json

Inspect every check. In particular, confirm no NaN/Inf or out-of-range values inside the footprint, one float32 band, and exact CRS/shape/transform equality. The validator checks local bytes only; it does not upload a file or reproduce the private DrivenData validator.

Authorized manual upload

Five steps after the “OK TO SUBMIT” release appears

GEMSDOE30 does not log in, submit, or choose the weekly slot. Use only an authorized competition account.

1. Confirm the release gate

On the project home page, look for the explicit green OK TO SUBMIT label. Check the run card, held-out DTI and 95% CI, duplicate check, and validator receipt. If the label is absent or says research-only, stop: do not upload an archive TIFF.

2. Download the named file

Click the one-click GeoTIFF link shown with the approved candidate. Verify the complete filename and SHA-256 against its JSON sidecar. Never rename an old raster to make it look like a new run.

3. Open the official competition form

Sign in to DrivenData, open DOE GEMS, select Submit, then Make new submission. The form accepts one single-band GeoTIFF or a ZIP containing one GeoTIFF. Follow current on-page instructions.

Open competition homepage ↗

4. Select the file and paste the unique note

Select the exact `.tif` you downloaded. Enter the candidate's unique name, then paste its associated note (maximum 140 characters) into Note (optional). The filename, note, and sidecar must refer to the same run.

Name: the exact run_name printed on the approved sidecar
Note: the matching short method note from that sidecar (≤140 characters)

5. Submit once and capture the receipt

After upload, save the organizer's submission ID/receipt, exact filename, SHA-256, note, submission date, public score, and whether it is public or private. Only an organizer receipt confirms a score-to-file association. A holdout result or projection is not a competition score.
