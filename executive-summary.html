Automated release gates

  1. Inputs and lane: verify pinned rasters, exact feature provenance, assigned method and complete shared registry.
  2. Leakage: withhold whole fault segments with a feature-support buffer. Recompute catalogue features from visible faults only; mask visible pixels exactly. Test each feature alone; AUC above 0.90 blocks trust until investigated.
  3. Performance: report HOLDOUT-DTI with evaluator version, withheld-positive count and spatial-bootstrap 95% CI. Pool sufficient statistics. Beat the best comparator rerun on the identical folds and corrected evaluator.
  4. Novelty: test the continuous surface before placement and final dots against every registry raster. Stop if rank correlation exceeds 0.90 or more than 70% of dots lie within 3 pixels of a reference.
  5. File contract: use the shared writer, then reopen the TIFF and verify one band, finite in-footprint [0,1] values, matching CRS, shape and transform. Record SHA-256 and outside-footprint convention.
  6. Release: publish the unique filename, note of at most 140 characters, exact validation receipt and run card. Research promotion does not allocate a weekly slot.

Prevent the range error without hiding defects

The error Predicted values must be in range [0, 1] requires inspecting the exact submitted bytes. The historical uploaded file is unknown, so its specific cause remains unproven. Feature nodata sentinels and a wrong footprint mask are plausible pipeline failure modes.

New predictions must pass the strict shared writer; do not silently clip invalid model output and call it a scientific success. The template—not a feature-band mask—defines the scoring footprint. 

.venv/bin/python scripts/validate_submission.py FILE.tif   --template data/raw/sample_submission.tif --json validation.json

# Separate strict whole-array diagnostic, not organizer approval:
.venv/bin/python scripts/validate_submission.py FILE.tif   --template data/raw/sample_submission.tif --finite-all-cells

The repository's published-format check expects NaN/null outside; its strict whole-array diagnostic instead requires finite values everywhere. The official reference notebook writes without an explicit nodata argument. These observations do not prove how the private portal handles every encoding. Record both checks separately; never promise immunity from portal rejection.

Upload procedure for a future selected candidate

  1. Confirm all automated gates passed and the separate selector allocated a slot under the current submission-page cap. That cap is not freshly verified here.
  2. Download the exact approved single-band .tif or a ZIP containing only it. Check its SHA-256 against the run card. Do not substitute a reference file or its twin encoding.
  3. Open the official competition using an authorized account and select New submission.
  4. Choose the approved TIFF under File to submit. Record the unique filename and copy its short note. Use the candidate name and note from the Download block at the top of this page (they are for your own team's reference).
  5. Save the organizer receipt, submission ID, exact file hash and returned result together. Only then label the result ORGANIZER-CONFIRMED.

No automated upload or human geological inspection is claimed or required by this project. Authentication and slot selection are separate operational requirements.
