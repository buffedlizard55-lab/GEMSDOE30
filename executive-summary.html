File contract

Before you upload

  • One GeoTIFF band; data type float32.
  • Projected CRS matches the provided grid: UTM zone 11N, EPSG:32611.
  • 100 m pixels and the exact template shape, bounds, and geotransform.
  • Every in-footprint value is finite and in the closed interval [0, 1].
  • Pixels outside the valid template footprint are null/NaN (the project's writer uses NaN and a NaN nodata tag).
  • Use the organizer-provided sample template; never invent the footprint or infer the grid from a screenshot.

These requirements are taken from the official competition problem description. The local validator checks them against the downloaded template but cannot guarantee portal acceptance.

Range-error fix

“Predicted values must be in range [0, 1]”

The message can be triggered by a NaN or infinity inside the valid footprint even when every ordinary numeric pixel appears to be in range. The earlier GEMSDOE25 site attributes one historical failure to in-footprint NaNs; that diagnosis is owner-reported, not an organizer-published validator rule.

  1. Run the file against the exact template, not just min()/max().
  2. Check the template mask: all valid cells must be finite and within [0,1].
  3. Check the outside mask separately: use null/NaN outside the footprint.
  4. Do not silently clip or rescale bad model values; fix the upstream model/output and rebuild.

Manual upload in DrivenData

Five steps, after the candidate clears holdout

The site does not submit files for you. An authorized competition account is required for the upload.

Download the candidate .tif

Use the download button at the top of this page. Confirm its unique filename and the SHA-256 recorded there. The 0.2600 artefact listed as the incumbent is a different, older file with a leaderboard score; the new candidate has none.

Open the official competition

Sign in through your authorized account, open the DOE GEMS competition, choose Submit in the sidebar, then Make new submission. The form describes a single-band GeoTIFF (.tif) or a .zip containing one GeoTIFF.

Open the competition homepage ↗

Choose the exact TIFF

Under File to submit, select the checked .tif file (or a ZIP containing only that one TIFF). Verify the filename matches the manifest and that the hash/size is the intended run.

Enter a unique name and short note

The generated filename is unique, for example GEMSDOE30_boundary300m_20261003T120000123456Z_ab12cd34.tif. Paste a short method comment in Note (optional) so future comparisons are identifiable.

GEMSDOE30 boundary300m | R=300m combined loss | run ab12cd34 | spatial holdout status: unverified

The example deliberately says “unverified”; replace it only with the actual frozen holdout result. The submission form's note is for distinguishing your submissions, not a place to claim an unverified score.

Submit and record the outcome

Submit once, wait for the platform's response, and save the submission ID, note, file SHA-256, public score, date/time, and whether the score is public or private. Do not infer a result from a local holdout or another project's page.

Local workflow

Create a real candidate only from real inputs

Data placement is the current blocker. The shell helper only checks local placement; it will not fetch login-protected files or store credentials.

python -m pip install -e '.[train,test]'
bash scripts/download_competition_data.sh
python scripts/prepare_data.py

# Train paired arms on the same buffered spatial fold and seed
python scripts/train_model.py --fold 0 --loss regional --output runs/fold0-regional.pt
python scripts/train_model.py --fold 0 --loss combined --output runs/fold0-combined.pt

# After all folds/seeds, infer, compare pooled DTI and near-miss profiles
python scripts/evaluate_loss_ablation.py --regional runs/regional.npy --combined runs/combined.npy

# Only after promotion: build / validate the full-data candidate
python scripts/infer_model.py --checkpoint checkpoints/promoted.pt
python scripts/validate_submission.py outputs/GEMSDOE30_....tif --template data/raw/sample_submission.tif

A single fold is only a screen. Use all frozen folds and fresh-seed confirmation before considering any weekly slot. The initial geometry weight is a test setting, not a selected optimum.

Competition limits worth remembering

  • The public leaderboard is not the private test set; a public increase can be overfit.
  • The official rules allow up to three weekly platform submissions and require one selected final submission for both prize rounds. Confirm current rules and deadline before any upload.
  • The public leaderboard changes over time. DrivenData Terms of Use prohibit automated monitoring/copying, so this page uses dated snapshots rather than a scraper.
  • The 2026 homepage and rules PDF show different deadline times (11:59 p.m. UTC versus 5:00 p.m. ET); confirm the controlling cutoff with the organizer.
  • Rules require a narrative disclosure of generative-AI use if applicable. Maintain a truthful method and tool-use record for the eventual submission package; the current-session disclosure draft must be updated and entrant-approved before use.
