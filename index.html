The “Predicted values must be in range [0, 1]” error is now diagnosed and engineered out — no longer “undiagnosed”.

Two mechanisms, both measured on this competition's own data this session. (1) training_features.tif encodes nodata as the float32 sentinel -3.4028234663852886e+38. All 19 bands carry it on 3,061 pixels inside the 5,167,373-pixel scoring footprint (band 6 tc: 3,073; 58,171 band-pixels in total). Left unsanitised, those cells ship values near −3.4×10³⁸. (2) The feature raster's own valid mask is smaller than the template's: band 1 calls 5,165,852 pixels valid against the template's 5,167,373 — so a footprint mask derived from a feature band strands exactly 3,061 scored pixels as NaN. Either defect alone produces the portal's range rejection. Full measurement record: range-error root cause.

How the shipped file is immune. scripts/build_portal_submission.py takes the footprint only from np.isfinite(sample_submission.tif), maps NaN→0.0, +Inf→1.0, −Inf→0.0, clips to [0, 1], writes zero outside, then re-reads the bytes from disk and asserts all 12,279,160 cells are finite and in range before it will exit 0. It fails closed: a grid mismatch or a surviving non-finite cell aborts the build. Covered by 7 unit tests in tests/test_portal_submission.py.

Is zero-outside legal? Yes, on two verified grounds. The organizer's own reference solution ↗ writes its example prediction with no nodata value at all and finite sigmoid output everywhere. And the owner ledger records r7-nms3-dem10-scarp_0c9199f14e62 = 0.1294 alongside …_allfinite = 0.1294 — the identical score for the NaN-outside and all-finite encodings, which shows outside-footprint cells carry no scoring weight. A NaN-outside twin with bit-identical in-footprint values is also linked if you prefer the literal spec wording.

The mechanism, from the published metric algebra. Because TPw takes a max over each truth pixel's 300 m neighbourhood, extra dots near an already-covered truth pixel add no TP but do add FPw. Substituting FNw = G − TPw into the published formula collapses it to DTI = TPw / (0.8·G + 0.2·(TPw + FPw)) — verified numerically to 1e-9 against src/gemsdoe30/metric.py on both dotted artifacts. Differentiating gives a clean break-even: a dot is worth adding iff its marginal TP credit per unit FP cost exceeds 0.2 × DTI (≈0.052 at DTI 0.26). Redundant dots have marginal TP = 0 and are therefore strictly harmful.

That predicts exactly the observed ordering. Portal score rises monotonically as dots are de-clumped: 121,131 dots at 100 m spacing → 0.1922; 60,069 at 200 m → 0.2477; 44,090 at 282.8–300 m → 0.2600. The winning minimum separation lands on the 300 m kernel radius itself — the scale at which two dots stop competing for the same truth pixels. This is the same effect this repo measured independently as the 6.38× Poisson-thinning multiplier (IR-30-033).

So the remaining lever is evidence, not thinning. d2.8 occupies only 0.85 % of the footprint; a 300 m hex packing could hold roughly 15× more dots. The file is evidence-limited, not packing-limited. Beating 0.2600 requires more non-redundant dots placed where un-catalogued faults actually are — i.e. a better score field over the 19 GeoDAWN bands — not a different emission schedule.

Do not read the catalogue-proxy column as a ranking. It orders GBM (0.19020) above d2.8 (0.16177), the reverse of the portal ordering. That inversion is expected: the real test set is expert-labelled faults absent from the catalogue, and catalogue pixels are masked out of scoring entirely. The proxy is a descriptive diagnostic only.
